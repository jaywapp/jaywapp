## 확인된 문제

1. 공개 프로필이 비공개 저장소 3개로 직접 연결한다.
2. 소개·기술 나열 뒤에 대표 프로젝트가 배치되어 실제 결과물에 도달하기까지 길다.
3. Bio와 고정 저장소가 새 README의 개발 생산성·AI 자동화 방향과 불일치한다.
4. CC JSONL Monitor는 Chrome Web Store에 게시되어 있으나 README의 안내는 미게시 상태다.
5. p4-harness와 cc-jsonl-monitor의 repository description/topics가 비어 있다.

## 결정과 범위

- 전문성: C#/.NET Windows 클라이언트 개발을 기반으로 개발 생산성 도구, AI 에이전트 하네스, 실용 웹 앱을 제작하는 엔지니어.
- 대표작: KeyMan, CC JSONL Monitor, p4-harness, Marvelog. 기존 경력과 보조 프로젝트를 보존한다.
- 사용자가 전면 개편과 적용을 위임했다. 동일 변경에 대한 추가 디자인 승인 절차를 만들지 않는다.
- 이 작업은 GitHub가 렌더링하는 README 편집과 SVG 브랜딩이다. 독립 웹 앱, 주요 제품 UX, 배포 환경 변경이 아니므로 샘플 웹 페이지·Supabase·Vercel 구성은 적용하지 않는다.
- 비공개 저장소의 공개 전환은 범위 밖이다. 기존 공개 소개 정보만 유지하고 비공개 소스로 향하는 링크를 제거한다.
- 팔로워·다운로드·절감률·직급·회사 업무 성과를 추정하거나 생성하지 않는다.
- 프로필 계정 설정(Bio·고정 저장소·설명·Topics)은 2026-11-06 로그인 후 적용·검증 완료했다.

## 완료 기준

- 새로운 README와 모든 참조 자산을 기본 브랜치에 원자적으로 게시한다.
- 이전 README는 Git 이력과 `docs/archive/`에 보존한다.
- 활성 README에는 비공개 저장소 링크와 잘못된 서비스 주소가 없다.
- GitHub 렌더링, SVG 이미지 로드, 주요 링크를 검증한다.
- 브라우저 로그인이 필요한 계정 설정은 문서 변경과 구분해 보고한다.
